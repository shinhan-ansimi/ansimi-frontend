# 안심이 프론트엔드 기획 정리


## 1. 기술 구성

| 항목 | 사용 기술 및 계획 |
| --- | --- |
| 프론트엔드 | React, TypeScript |
| 앱 형태 | PWA |
| 스타일 | Tailwind를 사용한 반응형 스타일 |
| 사용자 위치 | 브라우저의 현재 사용자 위치 가져오기 기능 |
| 지도 | 카카오 SDK 관련 기능 활용 |

### PWA 선택 이유 및 사용 환경

- 핸드폰에 설치해서 사용한다.
- React Native보다 간단하게 사용하기 위해 PWA를 선택한다.
- 스마트폰 화면에서 사용하기 좋도록 반응형으로 구현한다.
- 화면이 꺼져도 백그라운드에서 돌아갈 수 있도록 구현할 계획이다. -> 실제 테스트 필요

## 2. 지도 활용 계획

- 지도 자체를 화면에 불러온다.
- 특정 구간에 대한 경로를 표시한다.
- 경로를 빨간색, 파란색, 초록색 등의 색으로 표시한다.
- 지도에 편의점, 병원, 가게 등의 안전시설을 표시한다. (여기서 안전시설이란, 스토킹이나 범죄에 대한 위협이 있을 때 도움을 요청할 수 있는 시설을 말한다.)

## 3. 주요 기능

1. 귀가 모드 시작 및 종료로 하고 시작 위치는 현재 자신의 위치, 종료 위치는 마커로 지정
2. 지도에 실시간 사용자 위치 표시
3. 구간별 경로를 위험 수준에 따른 색으로 구분하여 표시
4. 지도에 편의점, 병원, 가게 등 표시

## 4. 화면 구성

화면은 총 두 개로 구성한다.

### 화면 1: 경로 설정

- 핸드폰 화면에 지도를 띄운다.
- 지도 위에 다음 정보를 겹쳐 배치한다.
  - 경로 시작 및 종료 부분
  - 경로에 대한 간단한 설명
  - 위험 수준
- 지도 위에 배치한다는 것은 PPT에서 요소를 겹쳐 배치하는 것과 같은 의미다.

### 화면 2: 사용자 위치 표시 및 경로 안내

- 전체 지도에서 현재 사용자 위치를 표시한다.
- 선택한 경로까지의 구간별 안내를 표시한다.

## 5. 화면 순서

경로 설정 화면 → 사용자 위치 표시 및 경로 안내 화면

## 6. 프론트엔드·백엔드·AI 역할

서비스의 안전도 평가 대상 지역은 서울로 지정한다.

| 담당 | 역할 |
| --- | --- |
| 프론트엔드 | 출발지·도착지 좌표를 백엔드에 전달하고, 응답받은 경로와 안전도 평가를 지도에 표시한다. 현재 사용자 위치와 구간별 이동 안내를 표시한다. |
| 백엔드 | Tmap에 탐색 옵션을 달리하여 도보 경로를 요청하고, 중복을 제거한 후보 경로를 AI 서비스에 전달한다. AI가 추천한 경로의 정보와 평가 결과를 합쳐 프론트엔드에 제공한다. |
| AI 서비스 | 보유한 서울 위험시설·범죄구간 데이터로 후보별 구간 안전도와 전체 안전도를 평가하고, 비교 기준에 따라 추천 경로를 선택한다. |

카카오 지도 SDK는 프론트엔드의 지도 표시를 담당하고, Tmap API는 백엔드에서 도보 경로를 가져오는 데 사용한다.

## 7. AI 안전도 평가에 사용하는 데이터

- AI 서비스에서 서울의 위험시설·범죄구간 데이터를 보유하고 활용한다.
- 데이터를 보유한다는 것은 AI 서비스가 데이터 저장소에서 필요한 정보를 조회하여 평가에 사용하는 것을 의미한다. 모델이 모든 데이터를 기억하도록 만드는 방식은 아니다.
- 전달받은 경로 좌표를 기준으로 주변 위험시설과 범죄구간의 위치를 비교한다.
- 경로가 범죄구간을 통과하거나 인접하는지 확인하고, 평가 기준에 따라 구간별 점수를 계산한다.
- 전체 경로의 안전도 점수와 구간별 점수·위험 수준·평가 이유를 반환한다.
- 점수 산정 기준, 전체 점수의 집계 방식, 위험 수준별 색상 기준은 개발 전에 정한다.
- 시간대를 평가에 활용하기로 정한 경우에는 백엔드가 이동 시간 정보도 AI 서비스에 전달한다.
- 데이터가 부족한 구간은 안전한 구간으로 간주하지 않고, 정보 부족 상태를 구분하여 반환한다.
- AI 서비스는 백엔드에서 전달받은 후보 경로를 동일한 평가 기준으로 비교하고, 안전도 점수가 가장 높은 경로를 추천한다. 안전도 점수는 높을수록 안전한 것으로 정의한다.
- 점수가 같을 때의 선택 기준, 허용할 우회 거리·시간, 데이터가 부족한 후보의 비교 방법은 개발 전에 정한다. 평가할 수 없는 후보를 안전한 경로로 추천하지 않는다.

안전도 점수는 보유한 데이터와 평가 기준에 기반한 결과이며, 실제 안전을 보장하는 값으로 정의하지 않는다.

## 8. 데이터 이동 순서

### 사전 준비

AI 서비스에서 서울 위험시설·범죄구간 데이터를 준비하고, 안전도 평가 기준을 정한다.

### 사용자 요청과 응답

1. **프론트엔드 → 백엔드**
   - 현재 사용자 위치를 출발지로, 지도 마커로 지정한 위치를 도착지로 사용한다.
   - 출발지·도착지의 위도와 경도를 보낸다.
2. **백엔드 → Tmap 경로 API**
   - 동일한 출발지·도착지에 대해 탐색 옵션을 달리하여 여러 번 요청한다.
   - 한 번의 요청에서 여러 대안 경로를 자동으로 받는 방식으로 가정하지 않는다.
3. **Tmap → 백엔드**
   - 각 요청에 대한 경로 좌표, 거리, 예상 소요 시간, 길 안내 정보를 반환한다.
   - 백엔드는 결과를 모아 중복 경로를 제거하고, 후보마다 경로 ID를 부여한다.
4. **백엔드 → AI 서비스**
   - 후보별 경로 ID, 경로 좌표, 거리, 예상 소요 시간을 목록으로 전달한다.
   - AI가 평가한 구간을 원래 경로와 연결할 수 있도록 구간 ID 또는 좌표 범위 등의 식별 기준을 함께 정한다.
5. **AI 서비스 내부 평가**
   - 보유한 서울 데이터에서 경로 주변의 위험시설과 범죄구간을 조회한다.
   - 후보마다 구간별 안전도와 전체 경로 안전도를 평가한다.
   - 후보별 평가 결과를 비교하여 추천 경로를 선택한다.
6. **AI 서비스 → 백엔드**
   - 추천 경로 ID와 추천 이유를 반환한다.
   - 후보별 전체 안전도 점수와 추천 경로의 구간별 점수·위험 수준·평가 이유를 반환한다.
   - 각 평가 결과가 어느 경로와 구간에 해당하는지 식별 정보를 함께 반환한다.
7. **백엔드 → 프론트엔드**
   - 추천 경로 ID에 해당하는 Tmap 경로 정보와 AI 평가 결과를 연결한다.
   - 추천 경로의 좌표, 길 안내, 거리, 예상 소요 시간, 전체·구간별 안전도를 프론트엔드용 응답으로 제공한다.
8. **프론트엔드 화면 표시**
   - 지도에 추천 경로를 그리고 구간별 위험 수준에 따라 색상을 표시한다.
   - 전체 안전도 점수, 거리, 예상 소요 시간을 표시한다.
   - 귀가 모드를 시작하면 현재 사용자 위치와 구간별 이동 안내를 표시한다.

```text
프론트엔드: 출발지·도착지 좌표 전송
    ↓
백엔드: 탐색 옵션을 달리하여 Tmap에 여러 번 요청
    ↓
Tmap: 요청별 경로 좌표·거리·예상 시간·안내 반환
    ↓
백엔드: 중복 제거 후 후보 경로 목록을 AI 서비스에 전달
    ↓
AI 서비스: 서울 데이터로 후보별 안전도 평가 및 비교
    ↓
AI 서비스: 추천 경로 ID·추천 이유·안전도 평가 반환
    ↓
백엔드: 추천 경로 정보와 평가 결과 통합
    ↓
프론트엔드: 지도·구간 색상·점수·거리·시간 표시
```

## 9. 경로·시설 표시와 안전도 평가의 구분

- Tmap 경로 응답에 주변 시설 목록이나 범죄 데이터가 자동으로 포함되는 것으로 가정하지 않는다.
- 안전도 평가용 서울 위험시설·범죄구간 데이터는 AI 서비스에서 조회한다.
- 지도에 표시할 편의점·병원·가게 등의 이름·종류·좌표를 AI 서비스의 보유 데이터로 제공할 수 있는지 먼저 확인한다. 부족한 경우 Tmap 장소 검색 API 등 별도 장소 검색 기능으로 확보한다.
- 현재 흐름은 Tmap에서 확보한 후보 경로의 안전도를 AI 서비스가 비교하고, 그중 추천 경로를 선택하는 방식이다. 서울의 모든 가능한 경로 중 가장 안전한 경로를 찾는다는 의미는 아니다.

## 10. 프론트엔드 구현 범위

현재 구간 판단, 이동 안내, 경로 이탈 감지, 도착 판단, 귀가 상태 관리는 프론트엔드에서 구현한다. 실제 경로 생성과 안전도 평가는 기존 역할 구분에 따라 백엔드와 AI 서비스에서 담당한다.

### 10.1 화면과 지도

- React·TypeScript·Tailwind로 스마트폰 반응형 화면을 구현한다.
- 주요 화면은 경로 설정과 귀가 안내의 두 개로 유지한다. 도착지 지정은 경로 설정 화면 내부 단계로 구성한다.
- 카카오 지도를 표시하고 지도 이동·확대·축소, 현재 위치로 이동하는 기능을 제공한다.
- 현재 위치를 출발지로 설정하고, 지도 마커로 도착지를 지정한다. 출발지·도착지 좌표와 선택 상태를 관리한다.
- 백엔드에서 받은 추천 경로를 지도에 표시하고, 구간별 위험 수준에 따라 경로 색상을 지정한다.
- 전체 안전도, 추천·평가 이유, 거리, 예상 소요 시간을 표시한다. 평가 불가 구간은 위험 수준과 별도로 구분한다.
- 제공받은 안전시설(병원, 가게 등)의 이름·종류·좌표를 지도 마커로 표시하고, 선택한 시설 정보를 보여준다.

### 10.2 백엔드 요청과 화면 상태

- 출발지·도착지 좌표를 검증한 후 백엔드에 경로를 요청한다. 프론트엔드에서 Tmap 경로 API나 AI 서비스를 직접 호출하지 않는다.
- 경로 계산과 안전도 평가가 끝날 때까지 처리 중 상태를 표시하고, 중복 요청을 방지한다.
- 요청 대기 시간을 제한하고 실패하면 재시도 버튼을 제공한다.
- 도착지 변경이나 재탐색으로 새 요청이 시작되면 이전 요청을 취소하거나 이전 응답을 무시하여, 오래된 결과가 최신 경로를 덮어쓰지 않도록 한다.
- 기본 상태는 도착지 선택, 경로 조회 중, 경로 확인, 귀가 진행, 재탐색 중, 도착, 종료, 오류로 구분한다.
- 별도의 진행 상태 API가 없다면 경로 조회와 AI 평가를 하나의 처리 중 상태로 표시한다. 실제로 전달받지 않은 세부 진행 상황을 표시하지 않는다.

### 10.3 현재 위치와 구간별 안내

- 귀가 모드 시작 시 브라우저 위치 추적을 시작하고, 현재 위치 마커를 갱신한다.
- 현재 위치와 경로의 선 구간을 비교하여 경로상 위치를 계산한다. 경로의 꼭짓점만 비교하지 않는다.
- 가까운 구간뿐 아니라 이전 진행 구간, 경로상의 순서, 이동 방향, 위치 정확도를 참고하여 현재 구간을 판단한다.
- 교차로나 평행한 길에서 구간이 반복해서 바뀌지 않도록 연속된 위치 갱신을 확인한다. 이동 방향을 얻을 수 없는 경우에는 다른 판단 정보를 사용한다.
- 다음 안내 지점까지의 거리는 경로를 따라 남은 거리로 계산하고, 해당 지점의 안내 문구를 표시한다.
- 지나간 안내 지점은 완료 처리하고, 남은 경로 거리를 갱신한다. 남은 시간을 갱신할 경우에는 초기 소요 시간과 구분하여 추정치로 표시한다.
- 위치 정확도가 낮거나 위치 갱신이 오래 끊기면 위치 확인 중 상태를 표시하고, 구간 진행·경로 이탈·도착 판단을 보류한다.

### 10.4 경로 이탈과 재탐색

- 현재 위치와 경로의 거리 차이를 확인하여 이탈을 감지한다.
- GPS 오차 한 번으로 재탐색하지 않고, 위치 정확도와 연속된 갱신 결과를 함께 확인한다.
- 이탈이 확인되면 현재 위치를 새 출발지로, 기존 도착지를 그대로 사용하여 백엔드에 경로를 다시 요청한다.
- 재탐색은 백엔드의 후보 경로 확보 및 AI 평가 흐름을 다시 사용한다. 프론트엔드가 새 경로나 안전도 점수를 직접 만들지 않는다.
- 재탐색 중복 요청과 반복 호출을 제한한다. 완료되면 새 경로와 안내 정보를 교체하고 구간 진행 상태를 초기화한다.
- 재탐색 실패 시 실패 상태와 재시도를 표시하고, 기존 경로를 참고용으로 유지하되 현재 위치와 맞지 않는 안내는 보류한다.

### 10.5 도착과 귀가 종료

- 도착지와의 거리, 마지막 경로 구간의 진행 상태, 위치 정확도를 함께 확인하여 도착을 판단한다.
- 도착이 연속된 위치 갱신으로 확인되면 도착 화면을 표시하고 위치 추적을 중단한다.
- 사용자가 직접 귀가 모드를 종료할 수 있도록 종료 버튼을 제공한다.
- 종료 시 위치 추적, 관련 타이머와 진행 중인 요청을 정리하고 저장된 진행 상태를 삭제한다.
- 도착 반경, 이탈 거리, 확인 횟수, 재탐색 간격은 조정 가능한 설정으로 분리하고 실제 스마트폰 이동 테스트로 값을 정한다.

### 10.6 귀가 상태 복원과 앱 복귀

- 새로고침 후 복원할 수 있도록 활성 귀가 상태, 경로 ID, 도착지, 필요한 경로·안내 정보와 저장 시각을 로컬에 저장한다.
- 전체 위치 이동 이력을 기본으로 저장하지 않고, 복원에 필요한 최소 정보만 유지한다.
- 새로고침 후 저장된 귀가 상태가 있으면 이어서 안내할지 사용자에게 선택을 제공한다. 오래되거나 유효하지 않은 상태는 폐기한다.
- 재개 시 현재 위치와 권한을 다시 확인하고, 위치에 맞게 현재 구간을 다시 판단한다. 필요하면 재탐색한다.
- 앱 전환·화면 잠금 후 복귀하면 위치와 경로 상태를 다시 확인한다. 갱신이 끊긴 동안 계속 추적했다고 표시하거나 중간 이동 경로를 임의로 복원하지 않는다.
- PWA 설치 설정을 구현하고, 대상 스마트폰에서 설치·잠금·앱 전환·복귀 동작을 실제 테스트한다.

### 10.7 예외 처리와 사용성

- 위치 권한 거부, 위치 수신 실패, 네트워크 오류, 경로 없음, AI 평가 불가를 구분하여 안내한다.
- 데이터 부족이나 AI 평가 실패 시 임의의 안전도 점수와 안전 추천 문구를 표시하지 않는다.
- 서울 밖의 위치나 평가 범위 밖 구간은 백엔드의 검증 결과와 연결하여 안내한다. 지도 선택 단계의 범위 안내는 프론트에서도 제공한다.
- 위험 수준은 색상뿐 아니라 텍스트로도 표시한다. 버튼은 스마트폰에서 누르기 쉽게 배치하고, 지도 위 카드가 주요 안내를 가리지 않도록 한다.

### 10.8 백엔드와 합의할 데이터 규격

| 데이터 | 프론트엔드 사용 목적 |
| --- | --- |
| 출발지·도착지의 위도와 경도 | 경로 요청. 좌표계와 배열 사용 시 좌표 순서를 명확히 합의한다. |
| 경로 ID와 순서가 있는 경로 좌표 | 경로 표시, 현재 위치와 경로 비교, 재탐색 결과 구분 |
| 구간 ID와 구간 좌표 또는 경로 내 범위 | 위험 색상과 AI 평가를 정확한 구간에 연결 |
| 순서가 있는 안내 지점의 좌표·문구·유형 | 다음 안내 선택, 남은 거리 계산, 안내 완료 처리 |
| 전체·구간별 점수, 위험 수준, 평가 이유, 평가 가능 여부 | 안전도 표시와 정보 부족 상태 처리 |
| 경로 거리와 예상 소요 시간 | 경로 확인 화면과 귀가 안내 화면의 정보 표시 |
| 시설 이름·종류·좌표 | 지도 마커와 시설 정보 표시 |
| 오류 코드와 평가 범위 상태 | 요청 실패, 재시도, 서울 밖·평가 불가 안내 |

점수 기준과 위험 수준의 경계값은 AI·백엔드와 공통으로 정한다. 프론트엔드는 전달받은 위험 수준을 합의한 색상에 연결하며 별도의 점수 기준을 만들지 않는다.

### 10.9 구현 및 검증 순서

1. SVG 시안을 참고하여 두 주요 화면과 도착지 선택 단계를 구현한다.
2. 합의한 예시 응답으로 경로·색상·점수·안내와 로딩·오류 상태를 구현한다.
3. 실제 지도와 현재 위치, 도착지 마커 선택을 연결한다.
4. 백엔드 경로 API를 연결하고, 평가 결과와 구간 표시를 검증한다.
5. 현재 구간 판단, 안내 진행, 경로 이탈·재탐색, 도착·종료를 구현한다.
6. 상태 복원과 PWA 동작을 연결하고 실제 스마트폰에서 검증한다.

검증에는 정상 이동뿐 아니라 교차로·평행한 길, 낮은 위치 정확도, 경로 이탈, 목적지 근처 통과, 요청 실패, 위치 권한 거부, 새로고침, 앱 복귀 상황을 포함한다.
